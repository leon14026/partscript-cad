# Partscript CAD

Browser CAD: OpenSCAD code in, STEP out, with jointed assemblies. Static site, no backend.

- **The plan for upcoming work is `docs/PLAN.md`.** Read its status notes at the top, then section 0 (rules), section 2 (measured facts) and section 3 (kernel cookbook) before changing engine code. Phases 1 to 5 and the Parts menu are done and live. Phases 6 (import STEP and STL) and 7 (Measure) are done and live (commit `df6cb0a`). Phase 9 (the user manual, `docs/MANUAL.md`) is done. Phases 8 (phone viewer) and 10 (open an assembly STEP as parts) are proposals, to be built in that order.
- **Keep `docs/MANUAL.md` true.** A change to the syntax of `part()` or `joint()`, to a build message, or to what the page does updates the manual in the same commit. `test/manual.test.ts` builds every example in it and compares printed messages and argument tables with the code. `public/manual.html` is generated from it by `npm run manual` and is not committed.
- Check your work before every commit: `npm run check && npm test && npm run build`. Then, if Playwright and Chrome are available, `python3 scripts/smoke.py` and `python3 scripts/smoke.py --software` (they read `dist/`, so build first).
- Pushing to `main` publishes the live site. Ask the owner first.
- The owner's own design files (the label fan folder) are not in this repository. Do not commit them. Keep probe scripts, test designs and STEP exports outside the repository too.
- Engine code is in `src/engine/`. Tests in `test/` run both WASM engines in Node: 180 tests, about a minute and a half.
- An exact build is never trusted alone. A part that uses `linear_extrude`, a `$fn` cylinder or a scaled matrix is compared with OpenSCAD's own fine mesh (`#agrees` in `build.ts`) and falls back to faceted on a mismatch. `unsupported()` in `csg.ts` and the exact builder must always agree about what is covered. A new exact feature needs a test with a volume worked out by hand.
- Imported files are `ProjectAssets` (bytes by name), apart from the text `ProjectFiles`; the worker keeps them between builds and a build names the ones it uses. An asset's solid is cached by the hash of its bytes. OpenCascade keeps the first mesh of a shape and there is no way to clear it, so a retry at a coarser setting does nothing: `previewSolid(..., imported)` picks the fineness from the face count before it meshes (`importedMeshing`). A STEP reads at about 0.8 s a megabyte, and meshing is about 9,000 triangles a second, so mind the 60 s job.
- OpenSCAD runs in a worker with about 1 MB of stack, and every nesting level of a CSG dump uses some of it. `renderMesh` flattens single-child `group()` blocks first (`flattenGroups`, fact F24). Do not feed it a raw BOSL2 dump.
- The measure tool reads faces, edges and corners by index in the order of `kernel.getSubShapes`, and `PartMesh.faceOf`, `edgeOf` and `corners` are numbered the same way (`previewSolid`, tested in `test/labels.test.ts`). Keep that order when changing how a preview is meshed. A preview mesh is made from the stored solid, after the BREP round trip, for that reason.
- Error messages are for a mechanical engineer, not a programmer: say what to change, name the file and line.
